# 六关玩法与验收入口
模块交互已更新：T模块制造 → 打击/科技两类，Y选载体 → 搭载 → 发射。具体费用、插槽、移除项目与当前验收入口以《2026-10-13_模块制造与投送改版.md》为准；下文早期模块名称和验收用时属于改版前记录。
本轮规则以冻橙确认的四项决定为准：第四关首艘必然离港、B可拦首艘，选择后15游戏秒接入第二轮；硅基人口依据信息流恢复，入侵负责限流；取消70%中心保护；第六关限时两类人口均清零。Windows试玩版入口仍为Builds/WindowsDemo/裁星计划Demo.exe，办公室和关内顶栏均可选择1–6关。

第四关流程：开局锁申请与拦截 → 第180秒首艘应急舰必然离港 → 右下通讯第一轮xxxxx → 继续 → A“让它逃出去吧”或B“不能放过” → 模拟继续15秒 → 同位置第二轮xxxxx与申请提示 → 结束对话开放申请。A本局关闭阻截（调试全开除外），B可拦首艘与后续舰。剧情期间模拟冻结，暂停/倍速作用于两轮间的15秒，所有阶段和倒计时随存档保存。
首次离港通过从地球初始人口中预留8P应急疏散人口实现，计入待清总人口但不能被常规打击提前删除；事件后转入真实舰船人口，不增加总人口，不直接标记外逃成功。只有飞出边界才计入外逃结局。飞离窗口第四关为90秒，保证第二轮15秒、申请25秒、载体制造15秒、阻截23秒的动作链仍有余量。事件时间、间隔、人数和占位文案均在DemoRules.json的solarStory中配置。
硅基恢复规则：当前人口大于0且低于初始人口 → 按初始人口×regenerationRate×regenerationScale×平均有效链条流速逐秒恢复，最多恢复到初始人口。3段指4节点之间的3条边，5段指6节点之间的5条边。任一端点被摧毁 → 对应链条流速永久为0；信息入侵 → 选中节点的相邻边临时限流；自动人口目标 → 压制第一条仍有流量的边。45秒后恢复流速，默认flowMultiplier=0可完全阻断，也可改成0.2等比例减速。信息入侵同时清24备份，不直接消灭硅基人口。病菌对硅基无效，对碳基按原周期结算。
查看方法：扫描 → 深度侦察 → 选中硅基星球 → 进入局部。节点之间出现流线，青色代表有流量，红色代表阻断；右侧显示文明类型、链条段数、平均流速和当前恢复速度。节点被摧毁及入侵到期会即时改变线条与恢复值。
调试入口：顶栏“调试” → 一键开启所有功能 / 一键恢复本关应有功能。全开绕过关卡解锁、研发前置和剧情功能门槛，不加资源、不跳剧情；恢复后重新按当前关卡、已有研发与A/B选择判定。第四关前正常模式不开放资源申请，第五、六关可直接使用大额确定性申请。
参数入口：DemoRules.json的layouts中填写species、populationShare、regenerationRate、scanExposureMultiplier、chainSegments和nodes；operations/infoVirus填写duration、flowMultiplier、effect和useLimit（0表示不限次数）。DemoCampaign.asset填写各关时间、人口和regenerationScale。旧nodeGate/protection字段为存档兼容保留，已经不参与伤害限制。迁移六关配置保留旧1–4关主要调参，更新文案、补足信息储备并取消保护，第3关时限至少900秒，第4关飞离窗口至少90秒；加入第5、6关。
验证文件：Docs/Validation/SixCampaign.txt为机制边界；SixPaidPlaythrough.txt为普通付费参考策略；SixUI目录为界面点击与截图。机制夹具会注入测试资源和侦察状态，普通付费策略不注入资源、第四关起正常申请，但自动完美校准；两者均不等于最终真人难度平衡。
本次构建已通过机制、配置及实际界面按钮验收，截图已人工核对。参考策略六关通关用时依次为2:29、5:56、13:25、7:56、7:34、6:49。后期大额申请会明显降低资源压力，因此这些结果只证明有可通关路径；第五、六关并未据此认定比第三关更难，难度梯度仍需试玩后调整。
